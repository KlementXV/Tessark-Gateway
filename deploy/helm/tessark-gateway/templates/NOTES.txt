{{- if .Values.customCa.enabled }}

⚠ customCa.enabled is true (beta): an ADMIN can attach a private certificate authority to a
  registry or an upstream source. TLS stays verified — a CA can never be combined with
  insecure TLS or an http:// URL, and the Gateway refuses the pair. Turning this back to
  false keeps the stored bundles but refuses any new transfer or mirror that needs one; a
  mirror's CronJob already installed in the cluster keeps running on its own schedule, so
  suspend or delete those mirrors *before* the upgrade:
    kubectl -n {{ .Release.Namespace }} get cronjob -l tessark.io/mirror-id
{{- end }}
{{- if not (or .Values.apiExternal.enabled .Values.mcp.enabled) }}

/api/mcp and the Swagger UI at /api/docs are routed by this Ingress like every other path —

⚠ Back up GATEWAY_SECRET_KEY, and back it up *together with* the database.
  It decrypts every stored registry/robot credential — losing it, or restoring the database
  from a backup taken with a different key, makes every credential permanently unreadable.
  Retrieve it with:
    kubectl -n {{ .Release.Namespace }} get secret {{ include "tessark-gateway.secretName" . }} -o jsonpath='{.data.GATEWAY_SECRET_KEY}' | base64 -d
